# Запуск с нуля: от регистрации до работающего ассистента

Инструкция для того, кто ставит ассистента первый раз. Занимает минут двадцать,
из них половина — ожидание установки.

## Что здесь вообще происходит

Языковая модель не «встраивается» в проект и не скачивается на компьютер. Claude
работает на серверах Anthropic. Наше приложение при каждом вопросе:

1. ищет подходящие нормы в своей базе документов (это происходит локально,
   бесплатно и без интернета);
2. отправляет найденные фрагменты вместе с вопросом в Anthropic;
3. получает готовый ответ и показывает его со ссылками на статьи.

Значит, купить нужно ровно одно: **доступ к API Anthropic**. Это не подписка
Claude Pro за $20 — подписка даёт доступ к чату claude.ai, но не к API.
Оплачивается отдельно, по факту использования.

## Шаг 1. Ключ Anthropic

1. Зайдите на <https://console.anthropic.com> и зарегистрируйтесь (можно через
   тот же аккаунт, что и claude.ai — это разные продукты с общим входом).
2. **Plans & Billing** → пополните баланс. Минимум — 5 долларов, этого хватит
   примерно на 100–150 вопросов на модели `claude-opus-5`. Для знакомства
   достаточно; кредиты не сгорают.
3. **Settings → API keys → Create key**. Скопируйте ключ (`sk-ant-...`) сразу:
   второй раз консоль его не покажет.

Сколько стоит вопрос: в модель уходит вопрос плюс 6 найденных фрагментов
(~3000 токенов), обратно — ответ (~600 токенов). На `claude-opus-5` это около
3–5 центов. Если поставить в `.env` `ANTHROPIC_MODEL=claude-sonnet-5`, выйдет
примерно вдвое дешевле при чуть более простых формулировках.

## Шаг 2. Установка

Нужен Python 3.10 или новее (<https://www.python.org/downloads/>; на Windows при
установке отметьте «Add python.exe to PATH»).

```bash
git clone https://github.com/mqalybek/AI-Agent-for-production.git
cd AI-Agent-for-production
```

Запустите `start.bat` (Windows) или `./start.sh` (macOS, Linux). При первом
запуске скрипт создаст файл `.env` и остановится — это ожидаемо.

## Шаг 3. Заполнить .env

Откройте `.env` в блокноте. Две строки, которые нужно поменять:

```
ANTHROPIC_API_KEY=sk-ant-...     ← ключ из шага 1
ADMIN_TOKEN=придумайте-пароль    ← этим паролем вы войдёте в админ-панель
```

`ADMIN_TOKEN` — это просто пароль администратора. Никуда регистрироваться не
нужно, вы придумываете его сами: например, `neft2026-admin-kz`. Кто знает этот
пароль — может загружать и удалять документы.

Запустите `start.bat` / `./start.sh` ещё раз. Теперь скрипт поставит зависимости,
проиндексирует документы (скачается модель поиска, ~80 МБ) и запустит сервер.

## Шаг 4. Открыть

| Что | Адрес | Как войти |
|---|---|---|
| Чат для пользователей | <http://127.0.0.1:8000/> | без пароля |
| Админ-панель | <http://127.0.0.1:8000/admin> | поле «Токен администратора» → ваш `ADMIN_TOKEN` |

В админ-панели первым делом нажмите **«Проверить ключ»** в блоке «Подключение к
Claude». Возможные ответы:

| Сообщение | Что делать |
|---|---|
| Ключ работает, ответы формирует модель… | всё готово, можно пользоваться |
| ANTHROPIC_API_KEY не указан в файле .env | вписать ключ и **перезапустить сервер** |
| Anthropic отклонил ключ | ключ скопирован не полностью, отозван — или сервер не перезапущен |
| Ключ принят, но доступ к модели закрыт | пополнить баланс в Anthropic Console |

> **Файл `.env` читается один раз при запуске.** Вписали ключ в уже работающий
> сервер — он этого не увидит: закройте окно с сервером (`Ctrl+C`) и запустите
> `start.bat` заново. Это самая частая причина, по которой ключ «не работает».

Проверка стоит доли цента: это настоящий запрос к модели, но на один токен.

## Шаг 5. Проверить на деле

Откройте чат и спросите что-нибудь по существу, например: «Какие сроки периода
разведки углеводородов?» Ответ должен прийти со ссылкой на статью Кодекса.
Разверните блок «Источники» и убедитесь, что норма процитирована та самая.

Дальше можно уточнять («а если это сложный проект?») — ассистент помнит разговор.
Если ответ неверный, нажмите **👎 Неверно** и напишите, что не так: замечание
попадёт в админ-панель, в раздел «Оценки пользователей».

## Шаг 6. Свои документы

Админ-панель → «Загрузить документ». Поддерживаются PDF, DOCX, TXT, MD.

Важное поле — **«Название документа»**: именно оно попадёт в ссылку на источник,
поэтому пишите так, как принято ссылаться: «Кодекс РК «О недрах и
недропользовании»», а не «kodeks_final_v2».

Галочки «Не индексировать разделы по темам» отсекают лишнее: для ассистента по
углеводородам разделы про уран и твёрдые полезные ископаемые — шум, который
только мешает поиску.

## Запуск из PowerShell

`start.bat` проще всего запускать **двойным кликом** в проводнике. Если хотите из
PowerShell — учтите две его особенности:

```powershell
cd "F:\AI Agent\AI-Agent-for-production-main\AI-Agent-for-production-main"
.\start.bat
```

Точка с обратным слэшем обязательна: PowerShell не ищет программы в текущей
папке, поэтому просто `start.bat` он не найдёт.

И ни в коем случае не `python start.bat` — так вы просите Python выполнить
пакетный файл как программу на Python, отсюда `SyntaxError: invalid syntax` на
первой же строке `@echo off`. Батник исполняет Windows, а не Python.

Команда `install requirements.txt` тоже не сработает: правильная форма —
`pip install -r requirements.txt`, но вручную её набирать не нужно, скрипт
ставит зависимости сам.

### Если батник капризничает — то же самое вручную

Четыре команды в PowerShell из папки проекта. Виртуальное окружение специально
не активируется: мы обращаемся к его Python напрямую, и это обходит запрет
PowerShell на запуск скриптов (`ExecutionPolicy`), о который спотыкается
`Activate.ps1`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env        # откройте .env и впишите ключ и пароль админа
.\.venv\Scripts\python.exe scripts\index_documents.py
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Последняя команда и есть запуск сервера: она не завершается, пока работает сайт.
Окно PowerShell после этого не закрывайте — можно свернуть.

## Если браузер пишет «Не удаётся получить доступ к сайту»

`ERR_CONNECTION_REFUSED` на `127.0.0.1:8000` означает ровно одно: **на вашем
компьютере сервер сейчас не запущен**. Адрес `127.0.0.1` — это «мой компьютер»,
никакого сайта в интернете по нему нет.

Проверьте по порядку:

1. **Окно с сервером открыто?** `start.bat` открывает окно, в котором должна
   висеть строка `Uvicorn running on http://127.0.0.1:8000`. Это окно нельзя
   закрывать — закрыли значит остановили сервер. Сверните его.
2. **Скрипт дошёл до конца?** Если он остановился на «Файл .env создан» —
   впишите ключ и пароль администратора и запустите скрипт ещё раз.
3. **Python установлен?** Откройте командную строку и наберите `python
   --version`. Если команда не найдена — переустановите Python с галочкой
   «Add python.exe to PATH».
4. **Порт занят?** Если в окне сервера написано `address already in use`,
   запустите с другим портом: `set PORT=8010` перед `start.bat`, тогда адрес
   будет `http://127.0.0.1:8010/`.

## Постоянный адрес в интернете

Пока сервер запущен на вашей машине, ассистент доступен только на ней: коллеги
по ссылке `127.0.0.1` попадут на свой собственный компьютер, а не к вам. Чтобы
появился настоящий адрес, приложение нужно поставить на сервер.

Самый короткий путь — Render, он умеет разворачивать проект прямо из
репозитория по файлу `render.yaml`, который уже лежит в проекте:

1. Зарегистрируйтесь на <https://dashboard.render.com>.
2. **New → Blueprint** → подключите этот репозиторий. Render прочитает
   `render.yaml` и создаст сервис с диском под индекс.
3. В настройках сервиса заполните две переменные: `ANTHROPIC_API_KEY` и
   `ADMIN_TOKEN`. В репозиторий они не попадают.
4. Через несколько минут сервис получит адрес вида
   `https://subsoil-law-rag.onrender.com` — это и есть ваш сайт.

Тариф нужен платный (от ~$7 в месяц плюс доллар-другой за диск): бесплатный
засыпает при простое и теряет данные, а вместе с ними индекс и загруженные
документы. Альтернативы с тем же Dockerfile — Railway, Fly.io или обычный
виртуальный сервер, где достаточно `docker run` (см. README.md).

**Прежде чем открывать доступ снаружи**, помните: чат не требует входа, его
увидит любой, у кого есть ссылка. Паролем закрыта только админ-панель. Если
ассистент для внутреннего пользования — ограничьте доступ VPN или сетью
компании.
