# RAG-ассистент по законодательству о недропользовании

Веб-приложение, которое отвечает на вопросы по нормативным документам о недрах
**только на основании загруженных файлов** и указывает источник каждого
утверждения (название документа + статья/пункт, при наличии — страница).

* **Backend** — FastAPI (Python).
* **Поиск** — гибридный: ChromaDB (вектора, косинус) + BM25, слияние по RRF.
* **Генерация ответов** — Anthropic API (Claude).
* **Админ-панель** — загрузка/обновление/удаление PDF, DOCX, TXT, MD.
* **Публичный чат** — вопрос → релевантные фрагменты → ответ со ссылками.

## Что уже в базе

| Документ | Что индексируется |
|---|---|
| Кодекс РК «О недрах и недропользовании» (№ 125-VI ЗРК, ред. 02.03.2026) | Общая часть + разделы по углеводородам |
| Единые правила по рациональному и комплексному использованию недр (приказ МЭ РК № 239, ред. 21.06.2026) | Разделы I–II и приложения по углеводородам |

Ассистент **предметный, по углеводородам**. Разделы про добычу урана, твёрдые и
общераспространённые полезные ископаемые и старательство в индекс не попадают
(фильтр тем в `app/sections.py`), а системный промпт прямо запрещает отвечать по
таким вопросам. Исходные файлы лежат в `documents/`, индексация — одной командой:

```bash
python3 scripts/index_documents.py --reset
```

Что именно выбрасывается, скрипт печатает при запуске:

```
Кодекс РК «О недрах и недропользовании»: 622 фрагментов
  выброшено [uranium] РАЗДЕЛ VIII. ДОБЫЧА УРАНА — 390 абзацев
  выброшено [solid_minerals] РАЗДЕЛ IX. РАЗВЕДКА И ДОБЫЧА ТВЕРДЫХ ПОЛЕЗНЫХ ИСКОПАЕМЫХ — 885 абзацев
  выброшено [prospecting] Глава 34. Старательство — 136 абзацев
```

Раздел, в заголовке которого перечислено несколько тем, целиком не
выбрасывается: из «РАЗДЕЛ X. ИСПОЛЬЗОВАНИЕ ПРОСТРАНСТВА НЕДР, СТАРАТЕЛЬСТВО,
ЗАКЛЮЧИТЕЛЬНЫЕ И ПЕРЕХОДНЫЕ ПОЛОЖЕНИЯ» уходит только глава про старательство, а
переходные положения — они действуют и для углеводородных контрактов — остаются.

Общие статьи, где уран лишь упомянут в перечислении рядом с углеводородами
(типовые контракты, залог права недропользования, переход права), сохраняются:
вырезать их нельзя, не потеряв углеводородную норму. За то, чтобы ассистент не
консультировал по урану, отвечает системный промпт.

## Важно про эмбеддинги

У Anthropic **нет собственного эндпоинта эмбеддингов** — компания рекомендует
сторонних провайдеров. Поэтому в проекте два режима векторизации
(`EMBEDDINGS_PROVIDER`):

| Значение | Что использует | Когда брать |
|---|---|---|
| `local` (по умолчанию) | `all-MiniLM-L6-v2` (ONNX) внутри chromadb | офлайн, без внешних вызовов и оплаты |
| `voyage` | Voyage AI (`voyage-3`), рекомендованный Anthropic | выше качество на русскоязычных нормативных текстах |

Генерация ответа в обоих случаях идёт через Claude.

> **Ставите первый раз?** Пошаговая инструкция от регистрации в Anthropic до
> первого ответа — в [SETUP.md](SETUP.md).

## Как запустить и начать пользоваться

Это не статический сайт: нужен Python-сервер, который держит поиск и ходит в
Anthropic. Поэтому GitHub Pages не подойдёт — приложение запускается на вашем
компьютере (или на сервере, см. ниже) и открывается в браузере как обычный сайт.

### 1. Что нужно один раз

* **Python 3.10 или новее** — <https://www.python.org/downloads/>.
  На Windows при установке отметьте «Add python.exe to PATH».
* **Ключ Anthropic** — <https://console.anthropic.com/settings/keys>. Ключ
  платный: вопрос стоит примерно 3–5 центов на `claude-opus-5` (по умолчанию),
  потому что вместе с вопросом в модель уходят найденные фрагменты документов.
  Если объёмы большие, поставьте в `.env` `ANTHROPIC_MODEL=claude-sonnet-5` —
  выйдет примерно вдвое дешевле.

### 2. Скачать проект

```bash
git clone https://github.com/mqalybek/AI-Agent-for-production.git
cd AI-Agent-for-production
```

Без git — кнопка «Code → Download ZIP» на странице репозитория, потом распаковать.

### 3. Запустить

**Windows:** дважды кликнуть по `start.bat`.
**macOS и Linux:** `./start.sh`

Первый запуск создаст окружение, поставит зависимости, попросит заполнить `.env`
и проиндексирует документы (скачается модель поиска, ~80 МБ). Дальше запуск
занимает пару секунд.

В `.env` нужно вписать два значения:

```
ANTHROPIC_API_KEY=sk-ant-...   ключ из консоли Anthropic
ADMIN_TOKEN=любой-пароль       им вы входите в админ-панель
```

### 4. Открыть в браузере

| Адрес | Что там |
|---|---|
| <http://127.0.0.1:8000/> | чат: задаёте вопрос, получаете ответ со ссылками на статьи и пункты |
| <http://127.0.0.1:8000/admin> | админ-панель: загрузка документов, статистика, проверка поиска |
| <http://127.0.0.1:8000/docs> | Swagger, если захотите дёргать API из своих скриптов |

Остановить сервер — `Ctrl+C` в окне терминала. Данные никуда не уходят: индекс и
загруженные файлы лежат в каталоге `data/` рядом с проектом, в облако
отправляются только ваш вопрос и найденные фрагменты — в Anthropic, ради ответа.

### Диалог: уточнения и возражения

Это чат, а не форма «вопрос-ответ». Ассистент помнит разговор, поэтому можно
спрашивать дальше, не повторяя контекст:

```
— Какие сроки периода разведки углеводородов?
— Не более шести последовательных лет [Кодекс…, Статья 116].
— А если это сложный проект?          ← ассистент понимает, о чём речь
— Ты не про то ответил, речь о продлении.
```

Под капотом два механизма. Во-первых, история реплик уходит в модель вместе с
вопросом. Во-вторых, перед поиском реплика переписывается в самостоятельный
вопрос («а если сложный проект?» → «какова продолжительность периода разведки
для сложных проектов?») — иначе поиск по фразе из трёх слов не нашёл бы ничего.
Переписыванием занимается дешёвая модель `claude-haiku-4-5`; если она недоступна,
поиск идёт по склейке с предыдущим вопросом, а не падает.

Диалог хранится на сервере (SQLite рядом с индексом) и переживает перезагрузку
страницы. Кнопка «Начать новый диалог» очищает контекст — полезно при переходе
к другой теме, чтобы прошлые реплики не тянули поиск в сторону.

Если сказать «ты ответил неверно», ассистент не станет ни спорить, ни соглашаться
машинально: он перечитает переданные фрагменты и либо признает ошибку с
исправленным ответом, либо покажет норму, которой подтверждается прежний вывод.

### Оценка ответов

Под каждым ответом две кнопки: **👍 Полезно** и **👎 Неверно**. По второй
открывается поле для замечания — «норма устарела», «не та статья», «ответ не про
сложные проекты». Оценка сохраняется вместе с вопросом и текстом ответа.

Всё это видно в админ-панели в разделе «Оценки пользователей», с фильтром
«только замечания». Так накапливается список реальных промахов: по нему видно,
чего не хватает в базе (например, нужен ещё один нормативный акт) и какие
формулировки вопросов ретривер обрабатывает плохо.

### Что работает без ключа Anthropic

Поиск по документам идёт локально: разбор файлов, векторный индекс и BM25
работают на вашем компьютере, бесплатно и без интернета. Платная только
формулировка ответа — её делает Claude.

Поэтому без ключа (и при исчерпанном балансе) ассистент не падает с ошибкой, а
отдаёт то, что нашёл: перечень относящихся к вопросу норм со ссылками на статьи
и пункты и полными цитатами в блоке «Источники». Связного ответа не будет, но
как поисковик по нормативке система работает.

Альтернатива платному API — локальная языковая модель (Ollama и подобные):
денег не стоит, но требует мощного компьютера с видеокартой, доработки кода под
другой SDK, а качество на русском юридическом тексте заметно ниже. Для
справочной системы по праву, где цена ошибки высока, это плохой размен.

### Сколько это стоит и как выбрать модель

Расход токенов **от модели не зависит**: в неё уходит один и тот же вопрос с
теми же шестью фрагментами документов. Меняется только цена за токен.

Реальный размер одного запроса в этом проекте — 12,5 тысяч символов, то есть
примерно 5500 входных токенов (системный промпт 2800 символов, фрагменты НПА
9600, вопрос) и около 1100 выходных на ответ со ссылками.

| Модель | Цена, вход / выход за 1M | Один вопрос | На $5 |
|---|---|---|---|
| `claude-opus-5` (по умолчанию) | $5 / $25 | ~5,5 цента | ~90 вопросов |
| `claude-sonnet-5` | $2 / $10 | ~2,2 цента | ~225 вопросов |
| `claude-haiku-4-5` | $1 / $5 | ~1,1 цента | ~450 вопросов |

Модель меняется строкой `ANTHROPIC_MODEL` в `.env` и перезапуском сервера.

Что выбрать: для юридических формулировок со ссылками на статьи разумный
компромисс — `claude-sonnet-5`. `claude-opus-5` точнее разбирает сложные
вопросы с несколькими нормами и лучше отказывается отвечать, когда норма не
нашлась. `claude-haiku-4-5` втрое дешевле Sonnet, но на нормативных текстах
чаще пересказывает норму своими словами вместо точной цитаты — для справочной
системы это риск, проверяйте на своих вопросах.

Чем ещё управляется расход (`.env`):

* `TOP_K` — сколько фрагментов уходит в модель. Шесть по умолчанию; четыре
  сократят вход примерно на треть, но по сложным вопросам ответ станет беднее.
* `CHUNK_SIZE` — размер фрагмента. Меньше фрагмент — меньше токенов, но норма
  чаще рвётся посередине.

Переписывание уточняющего вопроса всегда идёт через `claude-haiku-4-5` и стоит
доли цента — на счёт это практически не влияет.

Фактический расход виден в админ-панели, в блоке «Расход на модель»: сколько
ответов, сколько токенов и во что это обошлось по прайсу. Точные списания —
в консоли Anthropic, раздел Usage.

### Как ассистент отвечает

Ответ строится только из найденных фрагментов и всегда одинаково устроен:
сначала краткий вывод, затем детали, где после каждого утверждения стоит ссылка
на норму, а в конце — дисклеймер. Под ответом интерфейс показывает сами цитаты с
процентом совпадения, чтобы ответ можно было проверить глазами.

```
Максимальная продолжительность периода разведки — не более шести
последовательных лет для участка недр, не относящегося к сложным проектам
[Кодекс РК «О недрах и недропользовании», Статья 116].

«В указанный период недропользователь вправе проводить на участке разведки
любые работы по поиску и оценке месторождений, включая их пробную
эксплуатацию» [Кодекс РК «О недрах и недропользовании», Статья 116].

Период разведки исчисляется со дня регистрации контракта на разведку и добычу
углеводородов [Кодекс РК «О недрах и недропользовании», Статья 116].

Ответ подготовлен автоматически на основании загруженных документов и не
заменяет консультацию квалифицированного юриста.
```

Чего ассистент не делает: не отвечает по памяти модели, не выводит нормы по
аналогии, не оценивает правомерность ваших действий и не прогнозирует исход
спора. Если норма не нашлась — прямо говорит об этом, и запрос к модели в этом
случае вообще не отправляется. Вопросы про уран и твёрдые полезные ископаемые
отклоняет: этих разделов в базе нет.

### На каком языке отвечает

На языке вопроса: спросили по-русски — ответ по-русски, по-казахски — по-казахски,
по-английски — по-английски. Модель Claude свободно работает со всеми тремя.

Прямые цитаты норм при этом всегда приводятся на языке оригинала документа, без
перевода — юридическую силу имеет только официальный текст. Если вы спросили
по-казахски, а в базе лежит русская редакция, ответ будет казахским, а цитата
останется русской с пояснением рядом. Чтобы и цитаты были на государственном
языке, загрузите через админ-панель казахские редакции актов (на «Әділет» они
публикуются параллельно с русскими) — они лягут в базу как отдельные документы.

### Если нужен доступ для коллег

Приложению нужен постоянно работающий Python-процесс и диск под индекс, поэтому
GitHub Pages и подобная статика не подойдут. Подойдёт любая машина, где можно
запустить Docker: виртуальный сервер за пару долларов в месяц, сервер внутри
компании или платформы вроде Render, Railway, Fly.io.

```bash
docker build -t subsoil-rag .
docker run -d -p 8000:8000 -v subsoil-data:/data --env-file .env subsoil-rag
```

Том `subsoil-data` держит индекс и загруженные файлы — без него они пропадут при
пересоздании контейнера.

Прежде чем открывать доступ снаружи, учтите: чат не требует входа — его увидит
любой, кто знает адрес; токеном закрыта только админ-панель. Поэтому наружу
приложение стоит выставлять за HTTPS-прокси (nginx, Caddy, Cloudflare) и
ограничивать доступ сетью компании или VPN. Ключ Anthropic лежит в `.env` на
сервере — в репозиторий он не попадает, `.env` в `.gitignore`.

## Как это работает

1. **Разбор.** `app/ingest.py` вытаскивает текст (`pypdf` / `python-docx`,
   таблицы читаются в порядке документа, поэтому приложения не отрываются от
   своего заголовка). Отбрасываются титул, оглавление и абзацы «Сноска. Статья
   38 с изменениями…» — это история правок, а не норма.
2. **Разметка.** `app/sections.py` строит иерархию «часть → раздел → глава →
   статья». Номер статьи (в подзаконных актах — сплошной номер пункта, «пункт
   102») идёт в `locator` и попадает в ссылку на источник, раздел и глава — в
   отдельные поля. Заголовки глав границу фрагмента задают, но отдельными
   фрагментами не становятся, иначе они забивают выдачу поиска.
3. **Нарезка.** Фрагменты по ~`CHUNK_SIZE` символов; **новая статья всегда
   начинает новый фрагмент**, перекрытие подрезается по границе абзаца.
4. **Индексация.** `app/store.py` кладёт фрагменты в ChromaDB с метаданными
   `doc_id / title / locator / chapter / page`. Повторная загрузка того же
   документа удаляет старые фрагменты по `doc_id` — дублей не остаётся.
5. **Поиск.** Гибридный (`app/retrieval.py`): векторная выдача ChromaDB и
   лексический BM25 сливаются по Reciprocal Rank Fusion. Лексическая часть на
   русском юридическом тексте даёт больше, поэтому её вес выше (1.0 против 0.6);
   с `EMBEDDINGS_PROVIDER=voyage` веса выравниваются.
6. **Ответ.** `app/rag.py` берёт `TOP_K` фрагментов, оборачивает их в блок
   `<документы>` с атрибутами источника и отправляет в Claude с жёстким
   системным промптом.
7. **Дисклеймер.** Системный промпт требует завершать ответ строкой о том, что
   это не заменяет консультацию юриста; сервер дополнительно дописывает её,
   если модель забыла, и отдаёт отдельным полем `disclaimer`.

## Гарантии «только по документам»

* Системный промпт запрещает использовать знания модели вне переданных фрагментов.
* Если поиск не нашёл ничего — **запрос к модели вообще не отправляется**,
  пользователь получает честное «в загруженных документах нет сведений»
  (`grounded: false`).
* Каждый ответ сопровождается списком источников с процентом сходства и
  цитируемым фрагментом — ответ можно проверить глазами.
* В админке есть «Проверка поиска» — показывает, что именно достаёт ретривер,
  без вызова модели (удобно подбирать `CHUNK_SIZE` и `TOP_K`).

## API

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| GET | `/api/health` | публичный | проверка живости |
| GET | `/api/documents` | публичный | список документов в базе |
| POST | `/api/ask` | публичный | вопрос → ответ + источники (`conversation_id` продолжает диалог) |
| GET | `/api/conversations/{id}` | публичный | история диалога |
| POST | `/api/feedback` | публичный | оценка ответа (`up`/`down` + замечание) |
| GET | `/api/admin/stats` | токен | документы/фрагменты/провайдеры |
| GET | `/api/admin/documents` | токен | список с метаданными |
| GET | `/api/admin/model-status` | токен | живая проверка ключа Anthropic |
| GET | `/api/admin/topics` | токен | темы, которые можно не индексировать |
| GET | `/api/admin/feedback` | токен | оценки пользователей (`?rating=down`) |
| POST | `/api/admin/documents` | токен | загрузка (`file`, `title`, `note`, `replace`, `exclude_topics`) |
| DELETE | `/api/admin/documents/{id}` | токен | удаление документа и его векторов |
| POST | `/api/admin/search` | токен | отладка ретривера без вызова модели |

Админские запросы требуют заголовок `Authorization: Bearer <ADMIN_TOKEN>`.


## Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ANTHROPIC_API_KEY` | — | ключ Anthropic (обязателен для генерации) |
| `ANTHROPIC_MODEL` | `claude-opus-5` | модель генерации |
| `EMBEDDINGS_PROVIDER` | `local` | `local` или `voyage` |
| `VOYAGE_API_KEY` / `VOYAGE_MODEL` | — / `voyage-3` | для `EMBEDDINGS_PROVIDER=voyage` |
| `CHROMA_DIR` / `UPLOAD_DIR` | `./data/...` | где лежат индекс и исходники |
| `ADMIN_TOKEN` | — | пароль админки; без него админка отключена (503) |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1200` / `200` | нарезка текста |
| `TOP_K` | `6` | сколько фрагментов уходит в контекст |
| `MAX_UPLOAD_MB` | `40` | лимит размера файла |

Каталог `data/` в git не попадает — индекс и загруженные файлы остаются локально.

## Про качество поиска

Локальная модель эмбеддингов `all-MiniLM-L6-v2` обучена на английском и русский
юридический текст различает плохо: по запросу «как часто замеряется пластовое
давление» она сама по себе поднимает статьи про участки недр. Именно поэтому
поиск гибридный — BM25 вытягивает точные термины. Если нужен максимум качества,
включите `EMBEDDINGS_PROVIDER=voyage`: `voyage-3` работает с русским полноценно.

Отладить выдачу можно в админке («Проверка поиска») или из кода:

```python
from app.store import get_store
for hit in get_store().search("периодичность отбора глубинных проб", 5):
    print(hit["score"], hit["document"], hit["locator"], hit["chapter"])
```

## Ограничения

* Сканы без текстового слоя не индексируются — нужен предварительный OCR
  (сервер вернёт понятную ошибку 422).
* Редакции документов в `documents/` фиксированы датой выгрузки: перед
  использованием сверяйтесь с актуальной редакцией в ИПС «Әділет».
* Токен админки один на всех; для продакшена стоит завести нормальную
  аутентификацию и HTTPS-прокси перед приложением.
* Ответы — справочные. Юридическую силу имеет только официальный текст акта.
